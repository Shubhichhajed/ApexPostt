# ApexPost Logistics Platform

.NET 10 / C# 14 solution for the ApexPost course project. Weeks 2–3 built the counter platform (MVC + SQL Server/EF Core 10). Week 4 adds the courier flow: **offline store → REST API → courier client**.

| Project | What it is |
|---|---|
| `src/ApexPost.Domain`, `ApexPost.Application`, `ApexPost.Infrastructure` | Week 2–3 domain, use cases and EF Core/SQL Server data layer (unchanged by Week 4 apart from new service methods). |
| `src/ApexPost.Web` | Week 2–3 MVC counter application. |
| `src/ApexPost.Courier.Offline` | **Part A.** Couchbase Lite store (`apexpost_courier`), `IScanRepository`, SQL++ queries, value indexes, outbox, change listener. |
| `src/ApexPost.Courier.Offline.Console` | **Part A.** Console harness (Add / Find / List Pending / Simulate Sync / Delete / Exit) with the fake uploader. |
| `src/ApexPost.Api` | **Parts B, C, D-I.** Versioned REST API, validation, ProblemDetails, OpenAPI + Swagger UI, JWT + roles, partner API key. |
| `src/ApexPost.Client` | **Part C6.** C# SDK generated by NSwag from `contracts/v2.json` at build time. |
| `src/ApexPost.Client.Consumer` | **Part C6.** Console app that uses the generated SDK. |
| `src/ApexPost.Courier` | **Part D-II.** Courier client: typed `ApexApiClient`, `AuthHeaderHandler`, resilience (retry/circuit breaker/timeouts), source-generated JSON, protected token storage, automatic offline sync. |
| `tests/ApexPost.UnitTests` | Domain, application, API validation/authorization/exception-handler and partner-key tests. |
| `tests/ApexPost.Courier.Tests` | Courier client tests: auth handler, retry/circuit breaker, JSON/ProblemDetails handling, uploader mapping. |
| `tests/ApexPost.IntegrationTests` | Week 3 SQL Server + WebApplicationFactory tests. |

## 2. Secrets (never committed)

All secrets go into user-secrets. `appsettings.json` only holds non-secret values with empty placeholders.

```powershell
# API (Week 4)
cd src/ApexPost.Api
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=(localdb)\MSSQLLocalDB;Database=ApexPostDb;Trusted_Connection=True;TrustServerCertificate=True"
dotnet user-secrets set "Auth:SigningKey" "<random string of at least 32 characters>"
dotnet user-secrets set "Partner:ApiKey" "<long random partner key>"
cd ../..
```

`Auth:Issuer` (`https://apexpost.local`) and `Auth:Audience` (`apexpost-api`) are in `appsettings.json` because they are not secret. A quick way to make a key: `[Convert]::ToBase64String((1..48 | % { Get-Random -Max 256 }))` in PowerShell or `openssl rand -base64 48`.

Week 3 MVC app secrets (`ConnectionStrings:ApexPost`, `DemoPasswords:*`, `Integration:ApiKey`) are unchanged — see section 7.

## 4. Parts B & C — REST API, OpenAPI, versioning, SDK

```powershell
dotnet run --project src/ApexPost.Api --launch-profile ApexPost.Api
```

- Swagger UI: `https://localhost:7001/swagger` (dropdown: **v1 (deprecated)** and **v2**)
- OpenAPI documents: `https://localhost:7001/openapi/v1.json`, `https://localhost:7001/openapi/v2.json`
- Health: `https://localhost:7001/health`
- Development token: `POST https://localhost:7001/dev/token` with `{"role":"Courier","courierId":"courier-demo-01"}` or `{"role":"Admin"}`

In Development the API applies the Week 3 migrations and its own additive migration on start-up (`Database:ApplyMigrationsOnStartup`). Shipments need at least one branch and a Standard shipping rate, which the Week 3 seeder creates.

`ApexPost.Api.http` has a success and a failure request for every endpoint in both versions, plus the 401/403/API-key cases.

### OpenAPI vs. the built-in generator vs. Swagger UI

- **OpenAPI** is the contract itself: a JSON/YAML description of paths, operations, parameters, schemas, response codes and security schemes. It is language-neutral; tools such as NSwag read it to generate clients. Our snapshots are in `contracts/`.
- **The built-in .NET generator** (`AddOpenApi()` / `MapOpenApi()` from `Microsoft.AspNetCore.OpenApi`) *produces* that document at run time from the controllers' metadata: routes, `[ProducesResponseType]`, XML comments, `[Tags]`, `[EndpointSummary]` and the route names (which become operationIds). Our document transformer adds the title, description, version, contact and the Bearer/API-key schemes.
- **Swagger UI** (`Swashbuckle.AspNetCore.SwaggerUI`) is only a *viewer*: a web page that reads `/openapi/v1.json` and `/openapi/v2.json` and lets you try requests (including the **Authorize** button). It does not generate anything, so there is only one generator in the project (no `AddSwaggerGen`).

Both the documents and Swagger UI are mapped in Development only. That is a convenience choice, not security: every endpoint is still protected by JWT/roles or the partner key.

### Generated client SDK

`src/ApexPost.Client` contains no hand-written client code for the API: its `OpenApiReference` runs **NSwag** against `contracts/v2.json` on every build and writes the client into `obj/`. The exact settings are in `ApexPost.Client.csproj` (and the same settings in `nswag.json` for the NSwag CLI). Extensions live next to it in `ApexPostClientExtensions.cs` (a DI helper, a wrapper that turns 404 into `null`, and a partial class on a generated DTO).

```powershell
# regenerate (just a build) and run the consumer against the running API
./tools/generate-client.ps1          # or tools/generate-client.sh
dotnet run --project src/ApexPost.Client.Consumer
```

The consumer registers the client with `AddHttpClient`, creates a shipment (Admin token), fetches it, uploads two scans (Courier token) and catches the 404 through the generated `ApexPostApiException<ProblemDetails>`. Tokens come from `/dev/token` automatically, or from `APEXPOST_ADMIN_TOKEN` / `APEXPOST_COURIER_TOKEN`.

After changing the API, refresh the contracts from the running service with `tools/refresh-contracts.sh` and rebuild the client.

## 5. Part D — security and the courier client

API security is described in [SECURITY.md](SECURITY.md): JWT bearer validation (issuer, audience, lifetime, signing key), `Courier`/`Admin` roles, the courierId ownership rule, the partner `X-Api-Key` middleware, HTTPS redirection and HSTS.

Run the courier client (with the API running):

```powershell
dotnet run --project src/ApexPost.Courier
```

1. **Login** – choose "Get a development token" and enter `courier-demo-01` (or paste a token). The token is stored encrypted, never printed or logged.
2. **New Scan** – saved to Couchbase Lite as `Pending` immediately; uploaded straight away if online.
3. **Pending Scans** – list plus the live count from the Part A change listener.
4. **Sync Status** – online/offline, circuit state, last sync time, last result, failures and retry count.

Offline demo: stop the API (or disconnect the network) and add scans – they stay Pending and the banner **"Server unavailable – working offline"** appears once the circuit opens. Start the API again: the connectivity monitor sees `/health` come back and uploads the Pending scans in batches of 20. Values and reasons: [RESILIENCE.md](RESILIENCE.md).

`ApexApi:Platform` in `src/ApexPost.Courier/appsettings.json` picks the base URL (`Windows` → `https://localhost:7001/`, `AndroidEmulator` → `https://10.0.2.2:7001/`).

## 7. Week 3 counter platform (MVC + SQL Server)

```powershell
dotnet user-secrets set "ConnectionStrings:ApexPost" "Server=(localdb)\MSSQLLocalDB;Database=ApexPostDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true" --project src/ApexPost.Web
dotnet user-secrets set "DemoPasswords:CounterClerk" "<password>" --project src/ApexPost.Web
dotnet user-secrets set "DemoPasswords:BranchManager" "<password>" --project src/ApexPost.Web
dotnet user-secrets set "DemoPasswords:Auditor" "<password>" --project src/ApexPost.Web
dotnet user-secrets set "DemoPasswords:Administrator" "<password>" --project src/ApexPost.Web
dotnet user-secrets set "Integration:ApiKey" "<partner key>" --project src/ApexPost.Web

# create the empty database with database/Create-ApexPostDb.sql, then:
dotnet ef database update --project src/ApexPost.Infrastructure --startup-project src/ApexPost.Web
dotnet run --project src/ApexPost.Web
```

Demo logins: `counterclerk1@apexpost.local`, `branchmanager2@apexpost.local`, `auditor3@apexpost.local`, `administrator4@apexpost.local` (passwords are whatever you set above). The seeder creates 5 branches, 20 staff, 30 products, 10 zones/rates and 200 historical transactions.

Idempotent schema script: `dotnet ef migrations script --idempotent --project src/ApexPost.Infrastructure --startup-project src/ApexPost.Web --output database/migrations/ApexPostDb-ef-generated-idempotent.sql`. SQL artefacts are in `sql/` (reporting queries, procedures, the atomic sale demo, blocking demo, indexes, least-privilege script). Index and plan evidence: [PERFORMANCE.md](PERFORMANCE.md).
